# 小红书笔记评分算法设计文档

## 1. 概述

本文档描述小红书爬虫（`xhs_spider.py` / `xhs_util.py`）中两套评分体系的设计原理、指标定义和演进历史。

---

## 2. 动量分析（Momentum）

### 2.1 设计目标

衡量笔记的**传播速度与增长趋势**，识别正在爆发的新内容。

### 2.2 评分维度

```
综合动量分 = 速率得分(35%) + 互动得分(30%) + 新鲜度得分(20%) + 互动量得分(15%)
```

| 维度 | 权重 | 公式 | 说明 |
|------|------|------|------|
| 互动速率 | 35% | `interact_count / note_age_hours` | 每小时平均互动量，衡量当前热度 |
| 互动密度 | 30% | `comment_count / interact_count` | 评论占互动总量比例，有真实区分度 |
| 新鲜度 | 20% | 分段权重，见下表 | 新笔记优先 |
| 互动量归一化 | 15% | `(interact - min) / (max - min)` | 同批次相对位置 |

> **注1**：动量分析里的互动密度已改为 `comment_count / interact_count`，即评论数占互动总量的比例。旧版本因 `interact_count = liked + collected + comment` 导致该值恒≈1，无区分度。

#### 新鲜度权重分段

| 笔记年龄 | 权重 | 说明 |
|----------|------|------|
| ≤ 24小时 | 1.0（满分） | 当日新内容 |
| ≤ 72小时 | 0.833 | 近三天 |
| ≤ 168小时 | 0.667 | 近一周 |
| > 168小时 | 0.5 | 较老内容 |

### 2.3 历史增长率

当同一 `note_id` 被多次爬取时，系统自动计算两次互动量的增长率：

```
历史增长% = (当前互动量 - 上次互动量) / 上次互动量 × 100
```

首次爬取显示为空，第二次起有数据。

## 3. 价值分析（Value）

### 3.1 设计目标

衡量笔记的**内容质量与深度价值**，识别值得长期关注的优质内容。与动量分析互补：动量看"速度"，价值看"质量"。

### 3.2 评分维度（当前版本）

```
价值综合分 = 收藏率(40%) + 互动密度(30%) + 评论率(30%)
```

| 维度 | 权重 | 公式 | 说明 |
|------|------|------|------|
| 收藏率 | 40% | `collected / liked` | 收藏代表"保存到稍后看"，深度价值最强 |
| 互动密度 | 30% | `collected / interact_count` | 收藏占总互动的比例，反映内容的保存意愿 |
| 评论率 | 30% | `comment / liked` | 讨论热度，反映内容引发共鸣的能力 |

所有维度在同批次笔记内做 min-max 归一化后加权求和，最终分数在 [0, 1] 之间。

### 3.3 分享率的弃用说明

小红书前端**不在笔记弹窗中展示分享数字**（只有图标，无数值），DOM 和搜索 API 均无法获取，导致 `share_count` 恒为 0。

演进过程：
- v1：`收藏率(35%) + 互动密度(25%) + 转化质量(20%) + 分享率(10%) + 评论率(10%)`
- v2：调整权重，互动密度发现恒为 1.0（bug）
- v3：修复互动密度为 `collected/interact_count`；分享率权重降为 0%，评论率提升至 30%

## 4. DOM 数据获取

### 4.1 关键选择器

小红书前端为 Vue SPA，组件使用 scoped CSS（`data-v-*` 哈希属性）。以下选择器基于 `livelist.htm` CSS 分析得出：

| 数据 | 主选择器 | 降级选择器 |
|------|----------|------------|
| 发布时间 | `[class*="date"][data-v-772fa76f]` | 弹窗内任何 class=date 且有 data-v-* 属性的元素 → `.date` |
| 标签 | `[class*="tag"][data-v-772fa76f]` | 同上降级 → `a[href*="/tag/"]` |
| 分享数 | `.share-wrapper .count` | `.buttons .count`（第4个） |
| 作者 UID | `a[href*="/user/profile/"]` | 弹窗内任意含 `/user/profile/` 的链接 |

> **注意**：哈希 `772fa76f` 是 note-content 组件的编译哈希，前端重新打包后可能变化。降级逻辑会自动适配。

### 4.2 发布时间格式解析

`_parse_chinese_time` 支持以下格式：

| 格式示例 | 说明 |
|----------|------|
| `3分钟前` | 相对时间（分钟） |
| `2小时前` | 相对时间（小时） |
| `昨天` | 固定偏移 -24h |
| `5天前` | 相对时间（天） |
| `3周前` | 相对时间（周） |
| `2月前` | 相对时间（月，按30天计） |
| `06-15` | 无年份日期（补当年，若在未来则退至上年） |
| `05-01` | 同上 |
| `2025-12-31` | 完整日期 |
| `2026-04-07 00:00:00` | 完整时间戳 |
| `编辑于 06-15` | 自动剥离前缀 |
| `发布于 2026-01-01` | 自动剥离前缀 |

## 5. 数据来源与局限

| 字段 | 来源 | 局限 |
|------|------|------|
| `liked_count` | 搜索 API | 准确 |
| `collected_count` | 搜索 API | 准确 |
| `comment_count` | 搜索 API | 准确 |
| `share_count` | 前端不提供 | **恒为 0，不可用** |
| `pub_time` | DOM（`.date` 元素） | 依赖选择器，哈希变化时需更新 |
| `tags` | DOM（`.tag` 元素） | 同上 |
| `interact_count` | 搜索 API | = liked + collected + comment 的加总 |
| `fans_count` | 后台 fetch 用户主页 HTML 解析 | 通过 `__INITIAL_STATE__` 或 meta 标签解析；已缓存到 `xhs_users` 表，同用户不重复请求 |
