# B站视频动量分析算法设计文档

## 1. 概述

### 1.1 设计目标

动量分析用于评估视频的**增长趋势**和**热度持续性**，帮助识别：
- 🔥 正在爆发的潜力视频
- 💪 持续热门的长青视频  
- 📉 增长乏力的过气视频
- ⭐ 粉丝转化率高的黑马视频

### 1.2 核心思路

**单次快照模式**：基于视频发布时间计算播放速率，结合粉丝转化率和互动密度，一次爬取即可得到动量分析结果。

评分维度（5个维度，全部归一化到 0~1）：
- **播放速率 (30%)**：播放量 / 视频年龄(小时)，衡量单位时间内的热度
- **粉丝转化率 (25%)**：播放量 / UP主粉丝数，衡量视频的“出圈”程度
- **互动密度 (20%)**：(点赞+投币+收藏+评论+弹幕) / 播放量，衡量内容质量
- **新鲜度 (15%)**：基于视频年龄的分段权重，新视频得分更高
- **播放量归一化 (10%)**：同关键词下的播放量相对位置

**历史数据增强**：当多次爬取同一视频时，会自动显示真实增长率作为参考。

### 1.3 粉丝转化率（Fan Conversion Rate）

**核心概念**：视频播放量与作者粉丝数的比值，用于衡量视频的"出圈"程度。

```
粉丝转化率 = 视频播放量 / 作者粉丝数

解读:
  转化率 > 100%：视频播放量超过粉丝数（视频被广泛推荐）
  转化率 > 500%：超级爆款（远超粉丝基础）
  转化率 > 10000%：新人爆款，极具潜力
  转化率 < 10%：主要靠粉丝观看（普通视频）
```

**为什么重要？**

| 场景 | 粉丝数 | 播放量 | 转化率 | 解读 |
|------|--------|--------|--------|------|
| 大UP主常态 | 100万 | 50万 | 50% | 正常发挥 |
| 大UP主爆款 | 100万 | 500万 | 500% | 算法推荐，超级热门 |
| 小UP主黑马 | 1000 | 50万 | 50000% | ⭐ 新人爆款，极具潜力 |
| 小UP主常态 | 1000 | 500 | 50% | 粉丝基础 |

## 2. 数据模型

### 2.1 视频数据表 `bili_videos`

存储视频完整信息，包含作者粉丝数：

```sql
CREATE TABLE bili_videos (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id INTEGER,
    av_id TEXT UNIQUE,
    bvid TEXT,
    title TEXT,
    url TEXT,
    play_nums INTEGER,
    danmakus INTEGER,
    favorites INTEGER,
    review INTEGER,
    coin INTEGER,
    share INTEGER,
    like_count INTEGER,
    uploader TEXT,
    uploader_uid TEXT,
    uploader_fans INTEGER,        -- 作者粉丝数
    uploader_level INTEGER,      -- 作者等级
    uploader_verified INTEGER,   -- 作者是否认证
    pubdate DATETIME,
    duration INTEGER,
    description TEXT,
    tags TEXT,
    category TEXT,
    fetched_at DATETIME
);
```

### 2.2 作者信息表 `bili_uploaders`

缓存作者信息，减少重复请求：

```sql
CREATE TABLE bili_uploaders (
    uid TEXT PRIMARY KEY,
    name TEXT,
    fans INTEGER,                 -- 粉丝数
    level INTEGER,                -- 等级
    verified INTEGER,             -- 是否认证
    fetched_at DATETIME           -- 拉取时间
);
```

**缓存策略**：作者粉丝数每 7 天更新一次，避免频繁请求。

### 2.3 历史数据表 `video_history`

每次爬取视频详情时，自动保存一份快照：

```sql
CREATE TABLE video_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    av_id TEXT NOT NULL,
    task_id INTEGER,
    play_nums INTEGER,
    danmakus INTEGER,
    favorites INTEGER,
    review INTEGER,
    coin INTEGER,
    share INTEGER,
    like_count INTEGER,
    record_time DATETIME          -- 毫秒级时间戳
);
```

### 2.4 数据积累过程

```
时间线:
```

## 3. 动量计算逻辑

### 3.1 数据状态分层

根据历史数据点数量和时间跨度，将视频分为四种状态：

```
┌─────────────────────────────────────────────────────────────────┐
│  Level 0: 首次采集 (1条数据)                                   │
│  ─────────────────────────────────────────────────              │
│  状态: first_record                                             │
│  说明: 仅能显示当前绝对值，无法计算动量                         │
│  处理: 按当前值排名，标记 "首次采集"                            │
├─────────────────────────────────────────────────────────────────┤
│  Level 1: 数据积累中 (2条数据，跨度 < 48小时)                  │
│  ─────────────────────────────────────────────────              │
│  状态: data_insufficient                                        │
│  说明: 数据噪音大，不建议计算动量                               │
│  处理: 显示 "数据积累中..."，按当前值排名                       │
├─────────────────────────────────────────────────────────────────┤
│  Level 2: 动量可计算 (≥2条数据，跨度 ≥ 48小时)                 │
│  ─────────────────────────────────────────────────              │
│  状态: momentum_ready                                          │
│  说明: 数据充足，可计算可靠动量指标                             │
│  处理: 计算完整动量指标，参与加权评分                           │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 各场景计算示例

#### 场景 A：首次采集（1条记录）

```
输入:
  video_history: [(play=10,000, time=Day1)]
  uploader_fans: 1,000

计算:
  conversion_rate = 10000 / 1000 = 1000%

输出:
  status: "first_record"
  指标: 动量类全部为 None
  排名: 按综合评分排序（包含转化率）
  提示: "首次采集，仅显示当前值"
```

#### 场景 B：数据积累中（2条记录，< 48小时）

```
输入:
  video_history: [
    (play=10,000, time=Day1 10:00),
    (play=15,000, time=Day1 14:00)  ← 仅间隔4小时
  ]
  uploader_fans: 1,000

计算:
  time_span = 4 小时 < 48 小时
  conversion_rate = 15000 / 1000 = 1500%

输出:
  status: "data_insufficient"
  动量指标: 全部为 None（不计算）
  转化率: 正常显示
  排名: 按综合评分排序（包含转化率）
  提示: "数据积累中（需≥48小时，当前4小时）"
```

#### 场景 C：动量可计算（3条记录，≥ 48小时）

```
输入:
  video_history: [
    (play=10,000, time=Day1),
    (play=15,000, time=Day2),
    (play=22,000, time=Day3)
  ]
  uploader_fans: 1,000

计算:
  time_span = 48 小时 ≥ 48 小时 ✓

  total_growth_pct = (22000 - 10000) / 10000 = 120%
  
  time_span_days = 48/24 = 2 天
  cagr_daily_pct = ((22000/10000)^(1/2) - 1) * 100 = 48.32%/天

  avg_incremental_pct:
    增量1: (15000-10000)/10000 = 50%
    增量2: (22000-15000)/15000 = 46.67%
    avg = (50% + 46.67%) / 2 = 48.33%

  conversion_rate = 22000 / 1000 = 2200%

输出:
  status: "momentum_ready"
  total_growth_pct: 120%
  cagr_daily_pct: 48.32%/天
  avg_incremental_pct: 48.33%
  conversion_rate: 2200%  ← 高转化率，小UP主爆款
```

## 4. 动量指标详解

### 4.1 核心指标

| 指标 | 符号 | 公式 | 含义 |
|------|------|------|------|
| **总增长率** | `total_growth_pct` | `(当前值 - 初始值) / 初始值 × 100` | 整体增长幅度 |
| **日均复合增长率** | `cagr_daily_pct` | `(当前/初始)^(1/天数) - 1) × 100` | 标准化的每日增长速度 |
| **增量均值** | `avg_incremental_pct` | `Σ(单次增长率) / 次数` | 增长的稳定性 |
| **粉丝转化率** | `conversion_rate` | `视频播放量 / 作者粉丝数` | 视频的"出圈"程度 |

### 4.2 指标特点

#### 粉丝转化率 `conversion_rate`
```
优点: 
  - 能识别小UP主的爆款视频
  - 不受UP主量级限制，横向可比性强
  - 直接反映视频被算法推荐的程度

缺点:
  - 大UP主的转化率通常偏低（粉丝基数大）
  - 需要额外请求获取作者粉丝数
  - 粉丝数变化会影响历史对比

示例:
  1000粉UP主，50万播放 → 转化率50000% (⭐ 超级爆款)
  100万粉UP主，500万播放 → 转化率500%  (普通爆款)
```

## 5. 加权评分算法

### 5.1 综合评分公式

**单次快照模式**（无需历史数据，一次爬取即可计算）：

```python
composite_score = 
    velocity_score × 0.30 +           # 播放速率（30%）
    conversion_score × 0.25 +        # 粉丝转化率（25%）
    engagement_score × 0.20 +        # 互动密度（20%）
    freshness_normalized × 0.15 +    # 新鲜度（15%）
    normalized_value × 0.10          # 当前播放量（10%）
```

所有分量均归一化到 [0, 1] 范围，综合评分也在 [0, 1] 之间。

### 5.2 各分量计算

#### 播放速率得分 `velocity_score` (30%)

```
play_velocity = play_nums / video_age_hours
velocity_score = min(play_velocity / max_velocity_in_set, 1.0)

其中:
  video_age_hours: 视频发布到现在的时长(小时)
  play_velocity: 视频每小时平均播放量
  max_velocity_in_set: 同关键词下最高播放速率

范围: [0, 1]
含义: 视频持续热度，值越高说明单位时间内播放量越多
```

#### 转化率得分 `conversion_score` (25%)

```
conversion_rate = play_nums / uploader_fans
conversion_score = min(conversion_rate / max_conversion_in_set, 1.0)

范围: [0, 1]
含义: 视频相对UP主粉丝基础的“出圈”程度
```

#### 互动密度得分 `engagement_score` (20%)

```
engagement_raw = (like_count + coin + favorites + review + danmakus) / play_nums
engagement_score = min(engagement_raw / max_engagement_in_set, 1.0)

范围: [0, 1]
含义: 互动质量，投币和收藏权重更高（因为代表更强的用户认可）
```

#### 新鲜度权重 `freshness_weight` (15%)

```python
def calculate_freshness_weight(video_age_days):
    if video_age_days <= 1:
        return 2.0      # 1天内的视频加权2倍
    elif video_age_days <= 3:
        return 1.7      # 3天内加权1.7倍
    elif video_age_days <= 7:
        return 1.4      # 7天内加权1.4倍
    elif video_age_days <= 14:
        return 1.2      # 14天内加权1.2倍
    elif video_age_days <= 30:
        return 1.1      # 30天内加权1.1倍
    elif video_age_days <= 90:
        return 1.0      # 90天内正常
    else:
        return 0.8      # 90天以上降权

# 归一化到 [0, 1]
freshness_normalized = (freshness_weight - 0.8) / (2.0 - 0.8)
```

#### 当前值归一化 `normalized_value` (10%)

```
normalized_value = (current_plays - min_plays) / (max_plays - min_plays)

范围: [0, 1]
含义: 该视频在同关键词下的播放量相对位置
```

### 5.3 评分示例

假设"服饰"关键词下有3个视频：

```
视频A (小UP主爆款):
  播放量 = 500,000
  粉丝数 = 1,000
  转化率 = 50000% (= 500.0)
  归一化 = (500000 - 20000) / (500000 - 20000) = 1.0
  CAGR = 200%/天
  动量得分 = min(max(300, 0), 500) / 500 = 0.6
  发布1天 → 新鲜度 = 2.0
  转化率得分 = 500.0 / 500.0 = 1.0 (最高)
  
  composite = 1.0 × 0.45 + 1.0 × 0.35 + 2.0 × 0.20
            = 0.45 + 0.35 + 0.40
            = 1.20  ← ⭐ 最高！黑马视频

视频B (大UP主爆款):
  播放量 = 500,000
  粉丝数 = 1,000,000
  转化率 = 50% (= 0.5)
  归一化 = 1.0
  CAGR = 200%/天
  动量得分 = 0.6
  发布1天 → 新鲜度 = 2.0
  转化率得分 = 0.5 / 500.0 = 0.001
  
  composite = 1.0 × 0.35 + 0.6 × 0.25 + 0.001 × 0.25 + 2.0 × 0.15
            = 0.35 + 0.15 + 0.00025 + 0.30
            = 0.80  ← 中规中矩

视频C (普通视频):
  播放量 = 20,000
  粉丝数 = 10,000
  转化率 = 200% (= 2.0)
  归一化 = 0
  动量得分 = 0.2
  发布30天 → 新鲜度 = 1.1
  转化率得分 = 2.0 / 500.0 = 0.004
  
  composite = 0 × 0.45 + 0.004 × 0.35 + 1.1 × 0.20
            = 0 + 0.0014 + 0.22
            = 0.2214
```

**结论**：小UP主的爆款视频（视频A）得分最高，符合预期！

## 7. 最佳实践

### 7.1 使用建议

1. **单次爬取即可分析**：无需等待历史数据积累
2. **粉丝数据可选**：有粉丝数据时转化率得分生效，无粉丝数据时其他维度仍正常工作
3. **多次爬取增强**：重复爬取同一关键词，会自动显示真实增长率
4. **关键词覆盖**：对多个关键词分别爬取，建立完整数据库

### 7.2 结果解读

| 综合评分 | 解读 | 操作建议 |
|---------|------|--------|
| > 0.6 | 🔥 黑马爆款，小UP主大爆发 | 重点关注，考虑跟进 |
| 0.4-0.6 | ✨ 热门爆款，综合表现优秀 | 持续观察 |
| 0.2-0.4 | 📊 稳定视频，中规中矩 | 正常更新 |
| < 0.2 | 📉 增长乏力，热度下降 | 减少投入 |

### 7.3 场景应用

| 场景 | 说明 |
|------|------|
| **发现潜力新人** | 通过高转化率识别小UP主爆款 |
| **监控爆款生命周期** | 观察播放速率和互动密度判断视频热度 |
| **竞品分析** | 对比同关键词下不同视频的表现 |
| **选题决策** | 根据动量数据判断哪些题材更受欢迎 |

## 8. 局限性说明

1. **播放速率假设**：假设播放量均匀分布在整个视频生命周期，实际上可能前期增长快后期放缓
2. **作者信息延迟**：粉丝数可能有 7 天缓存延迟
3. **权重主观性**：0.30/0.25/0.20/0.15/0.10 的权重是经验值
4. **API 限制**：爬取频率受 B 站反爬机制限制
5. **转化率局限**：大UP主的转化率通常偏低，但不代表视频不好
6. **互动密度局限**：未区分互动的质量差异（如投币比点赞更有价值）
