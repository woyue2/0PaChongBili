# B站视频动量分析算法设计文档

## 1. 概述

### 1.1 设计目标

动量分析用于评估视频的**增长趋势**和**热度持续性**，帮助识别：
- 🔥 正在爆发的潜力视频
- 💪 持续热门的长青视频  
- 📉 增长乏力的过气视频

### 1.2 核心思路

通过**时间序列数据**对比同一视频在不同时间点的指标变化，计算复合增长率、增量均值等统计指标，结合视频新鲜度进行加权评分。

## 2. 数据模型

### 2.1 历史数据表 `video_history`

每次爬取视频详情时，自动保存一份快照：

```sql
CREATE TABLE video_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    av_id TEXT NOT NULL,           -- 视频AV号
    task_id INTEGER,               -- 关联爬取任务
    play_nums INTEGER,             -- 播放量
    danmakus INTEGER,              -- 弹幕数
    favorites INTEGER,             -- 收藏数
    review INTEGER,                -- 评论数
    coin INTEGER,                  -- 投币数
    share INTEGER,                 -- 分享数
    like_count INTEGER,            -- 点赞数
    record_time DATETIME           -- 记录时间（自动生成）
);
```

## 3. 动量计算逻辑

### 3.1 数据状态分层

根据历史数据点数量和时间跨度，将视频分为四种状态：

```
┌─────────────────────────────────────────────────────────────────┐
│  Level 0: 首次采集 (1条数据)                                   │
│  ─────────────────────────────────────────────────              │
│  状态: first_record                                             │
│  说明: 仅能显示当前绝对值，无法计算动量                         │
│  处理: 按当前值排名，标记 "首次采集"                            │
├─────────────────────────────────────────────────────────────────┤
│  Level 1: 数据积累中 (2条数据，跨度 < 48小时)                  │
│  ─────────────────────────────────────────────────              │
│  状态: data_insufficient                                        │
│  说明: 数据噪音大，不建议计算动量                               │
│  处理: 显示 "数据积累中..."，按当前值排名                       │
├─────────────────────────────────────────────────────────────────┤
│  Level 2: 动量可计算 (≥2条数据，跨度 ≥ 48小时)                 │
│  ─────────────────────────────────────────────────              │
│  状态: momentum_ready                                          │
│  说明: 数据充足，可计算可靠动量指标                             │
│  处理: 计算完整动量指标，参与加权评分                           │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 各场景计算示例

#### 场景 A：首次采集（1条记录）

```
输入:
  video_history: [(play=10,000, time=Day1)]

输出:
  status: "first_record"
  指标: 全部为 None
  排名: 按当前播放量 10,000 排名
  提示: "首次采集，仅显示当前值"
```

#### 场景 B：数据积累中（2条记录，< 48小时）

```
输入:
  video_history: [
    (play=10,000, time=Day1 10:00),
    (play=15,000, time=Day1 14:00)  ← 仅间隔4小时
  ]

计算:
  time_span = 4 小时 < 48 小时

输出:
  status: "data_insufficient"
  指标: 全部为 None（不计算）
  排名: 按当前播放量 15,000 排名
  提示: "数据积累中（需≥48小时，当前4小时）"
```

#### 场景 C：动量可计算（3条记录，≥ 48小时）

```
输入:
  video_history: [
    (play=10,000, time=Day1),
    (play=15,000, time=Day2),      ← 间隔24小时
    (play=22,000, time=Day3)       ← 间隔48小时
  ]

计算:
  time_span = 48 小时 ≥ 48 小时 ✓
  is_time_valid = True

  current = 22,000 (最新)
  previous = 10,000 (最早)

  total_growth_pct = (22000 - 10000) / 10000 * 100 = 120%
  
  time_span_days = 48/24 = 2 天
  cagr_daily_pct = ((22000/10000)^(1/2) - 1) * 100
                 = (2.2^0.5 - 1) * 100
                 = (1.4832 - 1) * 100
                 = 48.32%/天

  avg_incremental_pct:
    增量1: (15000-10000)/10000 = 50%
    增量2: (22000-15000)/15000 = 46.67%
    avg = (50% + 46.67%) / 2 = 48.33%

输出:
  status: "momentum_ready"
  total_growth_pct: 120%
  cagr_daily_pct: 48.32%/天
  avg_incremental_pct: 48.33%
```

## 4. 动量指标详解

### 4.1 核心指标

| 指标 | 符号 | 公式 | 含义 |
|------|------|------|------|
| **总增长率** | `total_growth_pct` | `(当前值 - 初始值) / 初始值 × 100` | 整体增长幅度 |
| **日均复合增长率** | `cagr_daily_pct` | `(当前/初始)^(1/天数) - 1) × 100` | 标准化的每日增长速度 |
| **增量均值** | `avg_incremental_pct` | `Σ(单次增长率) / 次数` | 增长的稳定性 |

### 4.2 指标特点

#### 总增长率 `total_growth_pct`
```
优点: 直观易懂，反映绝对增长
缺点: 不考虑时间跨度，无法横向比较

示例: 
  视频A: 1000→2000 (增长100%，用了30天)
  视频B: 1000→2000 (增长100%，用了1天)
  → 两者总增长相同，但视频B更火爆
```

#### 日均复合增长率 `cagr_daily_pct`
```
优点: 标准化时间，可比较不同跨度的视频
缺点: 短时间内数值会非常高

示例:
  视频A: 1000→2000 (30天) → CAGR = 2.35%/天
  视频B: 1000→2000 (1天)  → CAGR = 100%/天
  → 视频B的增长速度是视频A的42倍
```

#### 增量均值 `avg_incremental_pct`
```
优点: 反映增长的稳定性
缺点: 需要至少3条数据

示例:
  视频A: 日增 50%, 30%, 40% → avg = 40% (稳定增长)
  视频B: 日增 100%, 10%, 5%  → avg = 38.3% (增长放缓)
  → 视频A更有持续爆发力
```

## 5. 加权评分算法

### 5.1 综合评分公式

```
最终得分 = f(当前值归一化, 动量得分, 新鲜度权重)

根据数据状态采用不同权重:
```

#### 场景 1：动量可计算（`momentum_ready`）

```python
composite_score = 
    normalized_value × 0.5 +  # 当前数据表现（50%）
    momentum_score × 0.3 +    # 动量趋势（30%）
    freshness_weight × 0.2    # 视频新鲜度（20%）
```

#### 场景 2：动量不可计算（`first_record` / `data_insufficient`）

```python
composite_score = 
    normalized_value × 0.7 +  # 当前数据表现（70%）
    freshness_weight × 0.3    # 视频新鲜度（30%）
```

### 5.2 各分量计算

#### 当前值归一化 `normalized_value`

```
normalized_value = (current - min) / (max - min)

其中:
  current: 视频当前指标值（如播放量）
  max: 同关键词下所有视频的最大值
  min: 同关键词下所有视频的最小值

范围: [0, 1]
含义: 该视频在同关键词下的相对位置
```

#### 动量得分 `momentum_score`

```
momentum_score = min(max(cagr_daily + 100, 0), 500) / 500

其中:
  cagr_daily: 日均复合增长率（百分比）

映射:
  cagr = -100% → score = 0
  cagr = 0%    → score = 0.2
  cagr = 50%   → score = 0.3
  cagr = 100%  → score = 0.4
  cagr = 200% → score = 0.6
  cagr = 400%+ → score = 1.0 (封顶)
```

#### 新鲜度权重 `freshness_weight`

根据视频发布时间调整，新视频给予更高权重：

```python
def calculate_freshness_weight(video_age_days):
    if video_age_days <= 1:
        return 2.0      # 1天内的视频加权2倍
    elif video_age_days <= 3:
        return 1.7      # 3天内加权1.7倍
    elif video_age_days <= 7:
        return 1.4      # 7天内加权1.4倍
    elif video_age_days <= 14:
        return 1.2      # 14天内加权1.2倍
    elif video_age_days <= 30:
        return 1.1      # 30天内加权1.1倍
    elif video_age_days <= 90:
        return 1.0      # 90天内正常
    else:
        return 0.8      # 90天以上降权
```

### 5.3 评分示例

假设"服饰"关键词下有3个视频：

```
视频A: 
  播放量 = 100,000 (最大值)
  归一化 = (100000 - 20000) / (100000 - 20000) = 1.0
  CAGR = 50%/天
  动量得分 = min(max(150, 0), 500) / 500 = 0.3
  发布1天 → 新鲜度 = 2.0
  
  composite = 1.0 × 0.5 + 0.3 × 0.3 + 2.0 × 0.2
            = 0.5 + 0.09 + 0.4
            = 0.99  ← 最高

视频B:
  播放量 = 50,000
  归一化 = (50000 - 20000) / (100000 - 20000) = 0.375
  CAGR = 10%/天
  动量得分 = min(max(110, 0), 500) / 500 = 0.22
  发布14天 → 新鲜度 = 1.2
  
  composite = 0.375 × 0.5 + 0.22 × 0.3 + 1.2 × 0.2
            = 0.1875 + 0.066 + 0.24
            = 0.4935

视频C:
  播放量 = 20,000 (最小值)
  归一化 = 0
  CAGR = 0%
  动量得分 = 0.2
  发布100天 → 新鲜度 = 0.8
  
  composite = 0 × 0.5 + 0.2 × 0.3 + 0.8 × 0.2
            = 0 + 0.06 + 0.16
            = 0.22
```

## 7. 最佳实践

### 7.1 数据积累建议

1. **首次使用**：先运行 1-2 周积累历史数据
2. **爬取频率**：建议每天爬取 1 次，确保数据点均匀分布
3. **关键词覆盖**：对多个关键词分别爬取，建立完整数据库

### 7.2 动量分析时机

```
推荐场景:
✅ 新视频发布 48 小时后 → 判断是否有爆款潜力
✅ 视频爆发期 → 监控增长是否可持续
✅ 长尾视频 → 评估是否还有生命力

不推荐场景:
❌ 视频发布 < 24 小时 → 数据太少，噪音大
❌ 只有 1 次爬取记录 → 无法计算动量
```

### 7.3 结果解读

| 综合评分 | 解读 | 操作建议 |
|---------|------|---------|
| > 0.8 | 🔥 热门爆款，持续增长 | 重点关注，考虑跟进 |
| 0.6-0.8 | ✨ 潜力视频，动量良好 | 持续观察 |
| 0.4-0.6 | 📊 稳定视频，中规中矩 | 正常更新 |
| 0.2-0.4 | 😐 增长乏力，热度下降 | 减少投入 |
| < 0.2 | 📉 过气视频，无活力 | 可放弃 |

---

## 8. 局限性说明

1. **需要历史数据**：首次使用无法立即计算动量
2. **数据点要求**：至少需要 2 条记录，跨度 ≥ 48 小时
3. **静态指标**：未考虑视频被推荐、上热门榜等外部因素
4. **权重主观性**：0.5/0.3/0.2 的权重是经验值，可能需要根据场景调整
5. **API 限制**：爬取频率受 B 站反爬机制限制
